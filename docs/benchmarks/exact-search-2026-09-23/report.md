# 精确搜索数量基准：2026-09-23

在 Apple M4 Pro、macOS 27.0、Xcode 26.3 上测试提交 `112e15d`。使用 `-O` 优化编译，同时保留 `DEBUG` 测试隔离，未修改主工作区的应用代码或用户历史数据。

测试使用合成标题，包含中文、英文、重音字符、Emoji 和 URL。每条标题严格为 100 或 1000 个 Swift Character。100 字符组接近当前真实历史的平均标题长度 95 字符，但不代表真实内容分布；真实标题中位数为 33 字符。未导出用户的标题内容。

- `all`：搜索 `clipboard`，每条标题开头命中，命中率 100%。
- `sparse`：搜索 `目标tokenA`，每 100 条有一条在末尾命中，命中率约 1%。
- `none`：搜索不存在的 `__no_match_123__`，命中率 0%。
- 相邻采样交替使用大小写形式，保持精确搜索的不区分大小写语义。每次校验结果数量。

纯匹配调用生产环境的 `Search.search(..., mode: .exact)`，在后台任务中执行，包含逐项取消检查；每组预热 5 次、测量 50 次。
搜索流程调用真实 `History.searchQuery` 并等待对应任务完成，包含 40 ms 输入合并等待、标题快照、后台匹配、结果更新、高亮信息、快捷键和选择更新；每组预热 3 次、测量 20 次。测试窗口隐藏，因此该指标不包含输入法和 SwiftUI 实际绘制到屏幕下一帧的延迟。

表内单位均为 **毫秒**，格式为 **中位数 / P95**。P95 取排序后第 ceil(0.95 × 样本数) 个样本。

## 主要结果

- 9999 条、每条 100 字符：纯匹配中位数分别为 5.063 ms（开头命中）、156.648 ms（末尾约 1% 命中）、92.481 ms（无命中）。
- 同一档位包含 40 ms 等待和结果更新后，分别为 90.193、208.247、139.937 ms；不包含屏幕绘制。
- 9999 条、每条 1000 字符：末尾匹配纯计算为 1567.221 ms，完整搜索任务为 1602.256 ms。长文本全量扫描仍是明显瓶颈。
- 先前约 4.7 ms 的一次测试只覆盖开头命中，不能代表所有精确搜索。

## 复现与原始记录

原始样本：[results.json](results.json)。临时测试补丁：[benchmark.patch](benchmark.patch)。补丁只增加测试方法、任务完成等待入口和停止测试剪贴板监听入口；不修改搜索算法。

在提交 `112e15d` 的独立工作树应用补丁后执行：

```sh
git apply /path/to/benchmark.patch
xcodebuild test -project Maccy.xcodeproj -scheme Maccy \
  -configuration Debug -destination "platform=macOS" \
  -only-testing:MaccyTests/SearchTests/testExactSearchScalingBenchmark \
  SWIFT_OPTIMIZATION_LEVEL=-O CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO
```

测试把 JSON 写入 `/tmp/maccy-exact-benchmark-results-20260923.json`。测试不向系统剪贴板写数据；测试宿主启动后关闭其剪贴板监听，使用独立设置和内存数据库。
结果是本机本次运行的测量值，不是响应时间保证；系统调度、标题字符组成、匹配位置和结果渲染会影响实际体验。精确搜索扫描标题，不读取原始图片文件。
